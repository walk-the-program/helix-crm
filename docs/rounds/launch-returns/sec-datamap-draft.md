# Helix CRM data map (draft) — LR-SEC-W3

Draft for the LR-SEC Opus lead to finalise. Every row is justified by code
read during this task (paths and line references are in the SEC-W3 return);
anything not directly verified is marked "not verified" rather than assumed.
Context: Tauri v2 desktop app, one owner per install, no server, no accounts,
no multi-tenancy. One workspace = one SQLite file plus a few sibling folders
under `~/Library/Application Support/com.clearpathdigital.helix/workspaces/<id>/`
(macOS) or the Windows equivalent.

FINDING for the lead: the export/save-PDF UI itself (excluded from SEC-W3's ownership, `src/features/invoices/**`) does not tell the owner this at the moment they save | No, unless the owner opens, emails or moves it |

## Findings this table depends on (see the SEC-W3 return for full evidence)

- Activities, tasks and recurring reminders are **not** removed or redacted
  when the contact, company or deal they reference is purged — the foreign
  key is `ON DELETE set null`, not cascade. A note logged against a customer
  can outlive that customer's own record entirely. Out of SEC-W3's ownership
  to fix (`src/db/repos/activities.ts`, `tasks.ts`, `recurringRules.ts` are
  not on the owned list); described precisely for the lead.
- A merge's "Merged X into Y" system activity (`src/db/repos/merge.ts`,
  `systemStatement`) embeds both records' display names in its `body` text,
  attached to the survivor. If the survivor is later purged, that sentence —
  and the loser's name inside it — survives via the same orphan-on-purge gap
  as above.
- No in-app action deletes a workspace's files or its keychain item. This
  round added a Help article and Settings copy describing the manual
  procedure (`src/features/help/lib/content.ts`, `HELP_WORKSPACE_REMOVAL`;
  `src/features/settings/components/WorkspacesScreen.tsx`); an actual
  "Delete workspace" command would need a Rust command (recursive folder
  delete + a keychain item delete that is allowed to touch `dbkey` under
  this one, explicit, owner-confirmed path) plus a registry mutation in
  `src/app/appSettings.ts` — both outside SEC-W3's ownership.
